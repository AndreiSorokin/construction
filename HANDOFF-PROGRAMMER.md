## 1. Модель данных прототипа (источник правды для Prisma-схемы)

Состояние — один объект `data` со срезами:

| Срез | Содержимое |
|---|---|
| `users` | id, login (уникален, регистронезависимо), key (пароль), name, role, departmentId, lead (для снабжения), **canPrice** (право менять цены в нарядах), avatarVer, theme |
| `departments`, `objects` (цвет, привязка пользователей), `catalogs` (справочник ТМЦ), `works` (списки расценок), `vehicles`, `ips` (подрядчики-ИП) | справочники |
| `chains[deptId][type]` | маршрут согласования заявок: массив `{approverId, label}` |
| `orderChains[deptId]` | маршрут согласования нарядов |
| `requests` | заявки, см. ниже |
| `orders` | наряды: number (НР-…), lines[{id,name,unit,qty,price}], month, ipId/ipName, chain, currentStageIndex, status, history, attachments (метаданные) |
| `dms, anon, events, announcements, notes, drafts` | личные сообщения, анонимка (без автора!), календарь, объявления, заметки снабжения, черновики |
| `counters` | нумерация по типам |
| `urgentLimit` | лимит «Срочно» в день (0 = без лимита, по умолчанию 3) |
| `logoW/logoH/brandingVer` | логотип (сам файл — отдельно, см. §3) |

**Заявка (`requests[i]`):** id, number (`ТМЦ-0001`…), type (`tmc | transport | quarry | funds | fuel | travel | repair`),
fields (типозависимые), items[{id,name,unit,qty, deliveredQty, eta, fulfilled, stock{…}}],
priority (`Срочно | Высокий | Обычный`), due, note, departmentId, objectId/objectName/objectColor,
requesterId, chain (снимок на момент создания), currentStageIndex,
status: `approval → supply → fulfilled → done` + `returned | rejected`,
assignee (снабженец), supplyStage, postponed, spent, supplyNotes,
attachments (ТОЛЬКО метаданные: id, name, mime, size, by, byName, at — **без dataUrl**),
history[{action, by, byName, stage?, comment?, at}],
**consolidated / sourceIds / sourceNumbers / consolidatedInto / wasConsolidated / fromConsolidated** (объединение).

Действия истории заявки: created, approved, rejected, returned, edited, stock, fulfilled,
confirmed, unconsolidated, withdrawn, resubmitted. Нарядов: created, approved, rejected, edited, resubmitted.

## 3. Хранение в прототипе и что с этим делать на сервере

Прототип живёт на `window.storage` (лимит ~5 МБ/ключ, режет частоту и параллельность). Поэтому в нём:

- данные разложены по 4 ключам: `supply:v11` (ядро, флаг `_sharded:1`), `supply:v11:req`, `supply:v11:ord`, `supply:v11:misc`;
- каждый файл — отдельный ключ `supply:v11:att:<id>`;
- все операции идут через **единую очередь** (по одной, зазор 200 мс), запись — только изменившихся ячеек,
  с фоновыми повторами (пауза растёт до 30 с); красная тревога — лишь после 60 с непрерывных отказов;
- при входе без изменений записи **нет вообще**;
- есть разовые миграции: вынос inline-фото в att-ключи и перекладка старого единого ключа в 4 ячейки.

**На сервере всё это НЕ нужно** — заменяется Postgres + S3 из `server/` и `client/`. Но обязательны эквиваленты:
файл сначала подтверждённо загружен (S3), только потом метаданные попадают в заявку; в ответах заявок — только метаданные файлов.
Ключ `supply:v11` менять нельзя, пока пользователи сидят на прототипе (их данные живут под ним).

## 4. Дельта v11 → v59 (что реализовать сверх текущего каркаса `server/` и `client/`)

### 4.1 Целостность и права
- **deleteUser**: чистит пользователя из всех `chains`/`orderChains`, снимает `assignee`,
  «перескакивает» зависшие этапы согласования заявок И нарядов (запись в историю
  «Согласующий удалён — этап снят автоматически»). Иначе заявки виснут навсегда.
- **Уникальность логинов**: автогенерация свободного `userN`; при ручном вводе дубликата — отказ с пояснением.
- **canPrice**: цену строк наряда меняет только пользователь с флагом или admin (и на API-уровне тоже);
  количество/удаление — любой согласующий на своём этапе.
- Кол-во/цена в нарядах клампятся к ≥ 0. Наряд без позиций согласовать нельзя.
- Отклонённый наряд: автор (или admin) правит состав и жмёт «Отправить повторно» → chain с нуля, action `resubmitted`.
- Ненастроенный маршрут: заявка уходит сразу в снабжение, НО с жёлтым предупреждением в форме
  и явной записью в истории. Не менять на молчаливый пропуск.
- 13 разрушительных действий — только через подтверждение (danger-диалог) с описанием последствий.

### 4.2 Заявки/снабжение
- Настраиваемый **лимит срочных** (`urgentLimit`, 0 = без лимита): подсказка в селекте
  «Срочно · сегодня N/L», блокировка при исчерпании, авто-понижение до «Высокий» на бэке createRequest.
- «Получено N» (deliveredQty) переживает правку заявки.
- Черновики per-user, повтор заявки («Повторить»), печать одиночная и пакетная, отчёты за месяц + печать.

### 4.3 Объединение заявок (сводные, СВ-####)
- consolidate: ≥2 активных заявок с позициями → сводная; исходные помечаются `consolidatedInto`, скрыты у авторов.
- В сводной виден блок «Из исходных заявок» (фото/комментарии источников).
- **fulfill сводной закрывает исходные**: статус fulfilled, позиции отмечены, `wasConsolidated`,
  история «Закуплено в составе сводной СВ-N — подтвердите получение», авторы снова видят заявки.
- **unconsolidate**: файлы сводной переносятся в первую исходную (`fromConsolidated: 'СВ-N'`, запись в историю);
  сводная с файлами/суммой уходит в архив (status rejected, attachments очищены — без дублей), пустая — удаляется.
  Текст подтверждения честно предупреждает про перенос файлов.

### 4.4 История и UI
- История заявки и наряда — кнопка «История · N» + модальное окно (свежие сверху, иконки по типу действия,
  кто/что/этап/комментарий/время). Постоянного блока в карточке нет.
- Мобильная шапка и сайдбар: только логотип, имя, колокольчик, «Выйти» (роль/отдел — в ЛК).
- Логотип: PNG с альфой или SVG как есть (никакого JPEG), рендер по пропорциям
  (`object-contain`, height фикс., width auto) — вход 72px/маленькие 30–34px. Аватар — PNG 320.
- Диалоги только собственные (DialogHost: confirm/prompt, danger, кастомный okText) — `window.alert/confirm/prompt` не использовать.

### 4.5 Надёжность файлов
- Порядок «файл подтверждён → метаданные в документ» обязателен и на сервере.
- Экспорт «полная копия» собирает вложения из заявок И нарядов, без дублей.
